## wasm32 / IndexedDB / workerd

pi-durable builds for wasm32-unknown-unknown with harness, scheduler, codemode, sessions and all storage backends except native SQLite; tools, images and native environments (process/fs/watch) are compiled out because they need the OS. Native-only code is selected by target, not feature, and on native the gated dependencies and seams are tokio/std re-exports, so native behaviour is unchanged (`cargo test -p pi-chord -p pi-telemetry -p pi-ai -p pi-durable`: 1491 passed, 0 failed). Host bindings are opt-in features that do nothing off wasm32: `indexeddb` (browser IndexedDB, `storage::indexeddb::web`) and `cloudflare` (Workers/Durable Object bindings); wasm-bindgen-futures is always present on wasm32. On wasm32, tasks, timers and clocks go through `pi_chord::rt` (pi-chord, pi-durable) and `pi_ai::utils::wasm` (pi-ai): the JS microtask queue, setTimeout/clearTimeout (a dropped sleep clears its timer) and the JS clock. Non-Send fetch futures are wrapped by `assert_send`, sound on single-threaded wasm32 (compile_error if atomics are enabled). pi-ai HTTP providers use reqwest's fetch backend; the Codex websocket, OAuth loopback, process credentials, mTLS/proxies, AWS DPoP (ring) and file access are unavailable on wasm32 and fail gracefully. `tests/wasm32_gate/check.sh` runs wasm32 clippy over all four feature combinations with disallowed-methods, rejecting direct tokio::spawn/tokio::time/runtime Handle/std clock calls.

IndexedDbStorage keeps the upstream on-disk format (stores, indexes, row shapes); reference-written and Rust-written databases are row-identical in both directions. Evidence: host model (tests/indexeddb_storage.rs 60/60: all 56 upstream cases replaying the reference's fake-indexeddb traces, plus interchange); headless Chrome 156 through the real crate (tests/indexeddb_browser/run.sh: conformance 26 plain + 26 across reopen, 2297 browser-vs-model differential checks, interchange both ways, a Session roundtrip, a faux-provider Harness turn with a tool call, timer-paced stream, durable receipt and close/reopen, and the Sleep-drop clearTimeout regression); real workerd (tests/workerd: storage conformance, alarm, upstream wake scenarios, and the same Harness turn over Durable Object SQLite with eviction between submit and resume, 34/34).

Remaining limits: no real model provider exercised on wasm32 (CORS/fetch unverified); OS-dependent providers unavailable there; Harness turns verified only with the faux provider; the browser suite needs Chrome, playwright-core and wasm-bindgen-cli 0.2.129 and is outside `cargo test`.
