## Embedded harness (pi-durable-jsrt)

The stock durable harness is re-hosted in-process. The stock task bridge (crates/pi-durable/examples/task_stock_bridge.rs) is compiled into dispatch/transport.rs via #[path] and driven over an in-process frame transport, so the embedded and stock gates share one Hub implementation rather than copies. Queued frames are pumped onto the JS thread with JsRuntime::post_task (not tokio, because every tokio worker may be blocked in a sync callback); sync requests block in transport.wait; callback.result is routed inline when the reader queue is empty; JS identity and handle semantics are kept. js/internal/harness-service.js ports the stock task adapter: built-in tasks are native, the clock is native unless Date.now is faked at Harness open, default timers use JS setTimeout so fake timers work. Context views cross as refs: entries keyed by (namespace, entry id) and messages as {$m:[entry,index]} cross once as frozen shared objects, matching upstream identity (the 150-step context case dropped from >5 s to ~2 s). Session::sweep() keeps the pending document-sweep timer as upstream #sweepDocuments does (regression session_retention::commits_keep_the_pending_sweep_without_rearming_the_host_timer), halving host round trips in the deep ownership chain (transport.wait 499k -> 232k; 23.5 s -> 19 s).

Evidence: 1372/1372 embedded harness cases in both retention modes across the 38 harness files (mappings/embedded-harness.json); stock gates green when run serially. The runner must be a release build (LTO off, codegen-units 16 suffices); per-task cost is thread-handoff latency (~7 round trips/task), so the deep ownership case is ~15–19 s at load 20–60 and can time out near load ~280.
