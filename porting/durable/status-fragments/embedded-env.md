## Embedded environment, tools, images, testing, telemetry and extension host

`@earendil-works/pi-durable/{env,env/node,tools,images,images/node,images/cloudflare,testing}` run in pi-jsrt over native pi-durable (crates/pi-durable-jsrt/src/dispatch/{env,env/host,tools,images,testing,telemetry}.rs). They dispatch directly rather than through the stock Hub: they call the same pi-durable functions as examples/env_stock_bridge.rs and support/builtin_bridge.rs, which share the error-code strings, and the Hub's JSON/base64 frames would cost most where Boa is the bottleneck. NodeExecutionEnv keeps upstream's node:fs boundary (text readers/flushFile via the runtime's fs/promises, spills via createWriteStream, so FileHandle spies and vi.mock("node:fs") apply; binary readers open natively because pi-jsrt's fs.open cannot express O_NONBLOCK/O_NOFOLLOW). Any JS ExecutionEnv reaches native code via js_env(describeEnv(env)). Env conformance runs natively against the JS env; storage conformance replays per-backend recordings through the storage's own methods; storage benchmarks are JS checked against the native definitions. Release runner, both modes, original timeouts: env-node 52/53, env-node-spill 1/1, env-node-conformance 51/51, env-line-scan 4/4, env-truncate 8/8, tools 35/36, tools-read-differential 2/2, tools-images 34/34, images-wasm-module 1/1 (the two skips are original platform skips); env_embedded 8/8. Debug runner: tools-images 31–32/34 from Boa speed.

Substituted dependency (runner only): `@silvia-odwyer/photon/photon_rs.js`, used only to build test fixtures, is served by photon-rs 0.3.3 compiled natively (same version and source as the package's wasm; only the surface the tests use), because wasmi interprets its encoders far beyond the 5 s timeouts. The .wasm stays in place for images-wasm-module. Boa patches: a %TypedArray%.prototype.set fast path for dense number arrays, and non-numeric typed-array property names skip CanonicalNumericIndexString (4M shared-array set calls 2843 -> ~1150 ms); the uncached typedArray.length getter in loop conditions has no contained fix. pi-jsrt fidelity: createWriteStream honours highWaterMark; grown WebAssembly.Memory buffers detach as in V8; node mode supports --import/--require/--input-type=module.

Embedded `@earendil-works/pi-telemetry` (root and /render; /testing unused and not served): InMemoryTelemetryContext records natively in pi_telemetry, with JS clocks driving timestamps. The embedded packages resolve nothing from node_modules, and no upstream telemetry source runs in the runner.

pi-coding-agent extension host: `pi_durable_jsrt::install` runs in the extension runtime, so extensions import @earendil-works/pi-durable[/…], @earendil-works/chord[/…] and @earendil-works/pi-telemetry[/…]. crates/pi-coding-agent/js/EXPORTS.md carries the per-export checklist: every pi-durable subpath equals upstream; chord root 8/27 with chord/node and chord/telemetry-sqlite unserved (host/contract/link/state/manager APIs outside the durable subset). tests/extensions_durable.rs (2/2) runs a Session commit/read and a faux Harness turn from an extension and imports every served subpath. Two pre-existing pi-coding-agent deadlocks fixed: cross-runtime session cleanup during dispose (now queued on the target runtime), and ModelRuntime::rebuild_providers holding the composition lock while snapshotting extension providers; extensions_context_api went from intermittent hangs to 50/50 clean runs at 4 threads.

One exception: the runner resolves `@earendil-works/pi-ai` to the pinned upstream packages/ai/src as test-host code, as the stock gate does. Durable/chord tests need pi-ai subpaths (/providers/faux, /providers/openai, /utils/*) the extension host glue does not serve, and that glue's Rust half (~2.1k lines of host ops in pi-coding-agent) is coupled to the extension Bridge. In the real consumer (the extension host) durable runs on pi-rs's native pi-ai. Extracting a shared `pi-ai-jsrt` crate is future work.
