## Design details that must survive continuation

- Standard `serde_json::Value` cannot represent lone UTF-16 surrogates. Actual reference operation streams produce them through truncation. Chord's `json::Value` and `JsonString` preserve these units, including object keys and operation payloads, and serialize them as JSON escapes. Do not replace them with lossy UTF-8 conversion.
- JSON numeric equality uses JavaScript numbers, and stringify follows JavaScript index-key ordering and number formatting.
- `json::Value` deserializes through raw JSON. Direct JSON serialization/deserialization preserves its strings. Avoid routing it through `serde_json::Value` or serde's buffered tagged-enum representation. Storage record decoders need raw-value dispatch, with regressions for nested lone-surrogate payloads.
- Durable record `kind`, family `key`, `requestId`, outcome reasons and other arbitrary string payloads use `JsonString`. The reference conformance suite explicitly distinguishes different lone-surrogate identities. Preserve them in every persistent index. Model messages are retained as lossless JSON wire records until provider conversion; provider/harness integration remains open.
- `TaskState` retains memos only in live variants. `SubmissionState` distinguishes input and passive-write lifecycles. `StorageWrite::Task` boxes the larger task record. Record and definition versions use `u64` to cover JavaScript's safe-integer range.
- `MemoryStorage::prepare_commit` resolves document copies and validates all global IDs/actions before mutation. `PreparedMemoryCommit::apply` is idempotent and rejects stale competing preparations. `commit` serializes adoption while allowing reads inside the callback. Prepared writes are immutable Rust borrows, rather than runtime-frozen JavaScript objects.
- SQLite operations enqueue at method call, independently of their returned waiters. A submitted transaction operation must execute before commit even if its waiter is dropped. The native regression reproduced a dropped write compared with the reference, then passed after lease checking and worker submission were protected by the same mutex.
- The current native tracker clones a draft tree and replay clones owned values. Reference overlay/copy-on-write allocation and retention behavior still needs work. Do not mark these modules fully verified based on semantic fixtures alone.
- `Change::apply_ops` and `DocDraft<JsonObject>::apply_ops` retain explicit structural edits even when their final JSON equals the base. Invalid replay or root validation leaves state and recorded operations unchanged. Opaque typed `DocDraft::update` still captures a final-value diff. The test adapter uses reference JS proxy capture, then Rust replays, validates, prepares, persists, adopts and publishes those operations. Full native mutation capture and embedded proxy bindings remain open. Settled changes release their base/state references; the weak watch revision table does not pin document roots.
- Transaction operations enqueue at method invocation and run independently of dropped waiters. A callback that settles with pending operations rejects after draining them; drafts and Tx handles become unusable immediately at settlement. Document slots retain distinct old/new incarnations when retirement races an acquisition.
- Backend adoption runs synchronously after durability, before the commit future resolves; publications wait for that resolution. Missing adoption, adoption failure, and backend rejection before/after adoption are separately handled. GuardedStorage exempts request/caller-abort errors only on reads, preserves the first failure identity and drains actual backend operations before closing.
- Session close seals admission synchronously and ends observers in close-listener registration order, then runs `before_close`, drains admitted commits/cleanup writes and closes storage. Cancelling a close waiter leaves cleanup running. Internal commit listeners and watches share registration order; each listener group is snapshotted at its own delivery boundary.
- TelemetryContext now has a nonbreaking `record_event` method for contexts holding an active span; the in-memory span forwards it to the existing `TelemetrySpan::add_event`. Durable's context-level entry/submission events use it. External recording adapters must implement this context capability too; full 1.4 dependency alignment remains open.
- Native revision operation shape is not canonical in Chord. Existing golden cases match exactly, and independently generated operations replay in the reference; broader shape/performance-sensitive cases remain to be mapped.
- Context waiting starts an independent Tokio task. Cancelling the waiter leaves that operation running, matching promise observation semantics. Watches strip the frame's cancellation, retain at most 100 pending frames, and stop without waiting for a callback already running.
- Task transitions, abort marks, reservations and decisive steps share the Session mutation line. An invocation ends inside its decisive step before releasing admission to later writes. A committed outcome/wait/sleep wins over a handler error. Close seals admission and ends observers before signalling/joining handlers. A task cannot create new owned work in the commit that finishes it; final owner validation rejects that commit, as the reference requires.
- Ownership indexes keep full records only for live tasks, immutable owner fields for terminal ancestors needed by live descendants, and no detached history after their final leaf settles. Background boundaries limit ordinary ownership, idleness and cancellation. New candidates are judged through the transaction overlay. Wait validation includes explicit joins and ordinary owned work.
- The stock task transport must begin each command synchronously in incoming order, before spawning its waiter. Otherwise an abort or close received behind a held reservation can miss the intended place on the Session line. Its initial attempt exposed a Vite alias that still selected the reference Harness; native execution-counter assertions rejected that false pass before the alias was corrected.
- A context baseline is an identity, not JSON equality: a later system message with equal content must not become the baseline. Native immutable message references preserve this identity across contributions, ordering and incremental reads. The test transport sends alias metadata to reconstruct the same references in JavaScript; plain JSON serialization lost them and the stock randomized test caught it.
- Context bounds are captured on the mutation line; the range scan runs off it and cannot observe edits/resets past the captured tail. A range can extend under the same head marker; an edit/head in newly scanned entries rederives contributions, and an earlier cutoff uses the retained prefix without another range scan. Background ownership boundaries still determine context idleness.
- Context ranges are kept only while their invocation is live and do not replace a newer retained tail. Closing seals retention and clears caches atomically. Detached reads and watch acquisitions continue independently of their waiters; watch binding itself must run eagerly so dropping its waiter cannot leave an observer outside invocation cleanup. Native regressions cover both dropped-waiter cases.
- The context stock runner uses a release binary. Its randomized 170-step transcript exceeded the unchanged five-second stock deadline under a debug build; with production optimization it finishes in about 1.4 to 2.0 seconds. No upstream assertion or timeout was relaxed. The stock test bridge retains native range leases only while their JavaScript range objects remain reachable; finalization sends ordered release notifications.
- No Node or TypeScript runtime is part of the new crate. Node is used only by fixture generators and the reference verifier.
- The user explicitly requires the stock pi-mono tests against Rust, not only native tests/fixtures. Keep expanding unmodified stock-suite execution as APIs land. The first complete stock file is `jsonl-storage.test.ts` (93 tests, run twice). - JSONL copies are resolved by MemoryStorage preparation before encoding. Ordinals increase across the whole commit, not per sidecar. Terminal tasks stay inline in `main.jsonl`; live tasks use sidecars. Marker append is the publication boundary. With `fsync`, sidecars flush before the marker; main flush is performed only when authorizing reclamation, as the stock ordering tests require.
- Reclamation is best-effort after adoption and must not poison the backend. Recovery can substitute empty bases for reclaimed current-only document prefixes, but requires every retained rewindable record. It removes unconfirmed sidecar tails, rejects confirmed records after an unconfirmed record, and ignores/removes matching reclaim temporary files.
